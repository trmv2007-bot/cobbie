# What a player can do, and what Cobbie can do today

Rishi's target for Cobbie is "everything a player can do in Minecraft". This document is the inventory of
that target: about 150 discrete capabilities, each with the exact game API that performs it, what Cobbie
actually does on `master` today, and what is genuinely still missing.

**It was stale, and this version is the audit that fixes that.** The third column was written at 0.18.1
and never updated, so by 0.86 it still said `no` to stairs, slabs, doors, signs, wall torches, containers,
furnaces, tilling, planting, bone meal, buckets, milking, shearing, leads, name tags, breeding, taming,
item frames, levers, buttons, note blocks, TNT, villager trading, redstone, enchanting, anvil, brewing,
smithing, loom, cartography, grindstone, XP and hunger — most of which shipped and was verified between
0.20 and 0.86. A stale map is worse than no map: it hides the real gaps behind work that is already done.

Audited at **0.87.0** against `src/main/java/com/rishi/cobbie` on `master` and against the in-game suite.
The three structural blockers the original survey named are the reason this took so long, and all three are
now closed; the three that replace them are below.

## How to read a row

| word | means |
|---|---|
| **yes** | the code path does it *and* a named in-game class proves it. The proof is quoted in the cell |
| **yes, by code only** | the mechanism is the API call the cell names and no in-game class isolates it; the nearest proof is named beside it. Honest, but weaker than `yes` |
| **partial** | real, but weaker than a player's. The fourth column names exactly what is missing |
| **untested** | the code path exists and nothing proves it. This is **not** a claim. Every one of these is a cheap test away from being a fact, and the fourth column says which |
| **no** | absent. The fourth column names what implementing it would need |
| **n/a** | a player capability a companion should not have, with the reason |
| free / incidental | it happens because the game does it for any `LivingEntity`; nothing in the mod implements it |

Bare line numbers are in `entity/CobbieEntity.java`; a path with a directory is that file.
`CobbieEntity.java` is 6,668 lines, so a line number here is a landmark, not a contract — the method name
beside it is the durable part of every citation.

## The three things that actually block parity now

The original survey named three: every player entry point takes a `Player`, he never touches a
`BlockEntity`, and nine slots is not an inventory. **All three are closed.**

1. **The fake actor exists.** `actor/FakeActor.java` is a cached, never-spawned `FakePlayer` that stands
   where Cobbie stands for one call and hands the held stack back. Every `useItemOn`, `ItemStack.use`,
   `interactOn`, menu and anvil call above goes through it. It costs what its own header says: other mods
   see an actor, advancement triggers fire for it, and any code path that opens a menu opens it into
   nothing — which is why the verbs that need a menu drive the menu directly (`FakeActor.enchant`,
   `applyBook`, `grind`, `weave`, `cartography`).
2. **Block entities are read and written.** `station/Containers.java` resolves the real `Container` behind
   a chest, barrel, shulker or furnace without opening anything; `startSmelt`, `startBrew` and
   `tradeWithVillager` drive the machines themselves. Furnace, brewing stand, stonecutter, anvil,
   enchanting table, loom, cartography table, grindstone, smithing table and every container are real.
3. **The bag is 45 slots.** `inventory_size` defaults to 45, clamped 1..54 (`CobbieConfig.java:172`), and
   shrinking it drops the surplus on the ground instead of deleting it (`CobbieBagMigrationTest`).

What replaces them is narrower, and none of it is plumbing:

1. **A right-click is one call; a bow is two.** Every remaining item gap is the same missing thing: a
   hold and a release. `ItemStack.releaseUsing`, the bow's charge, the crossbow's loaded state and the
   trident's throw all need the actor to keep using an item across ticks, and the actor makes one call and
   lets go. Everything that is a single click already works, which is why the list of `no`s is so short.
2. **His body is a mob's body.** No `Pose.SNEAKING`, no crawl dimensions, no air supply, no fall-flying,
   no sleeping, no riding a saddled animal. These are `Player` state or `EntityDimensions`, not verbs, and
   a `PathfinderMob` cannot have them without becoming something else.
3. **Taste, not reach: what he does not choose.** He mines a block with the cheapest tool that harvests it,
   which is a policy that reads as a capability gap and is not one. The other half of this — that he would
   not attack an animal at all — **closed at 0.89.0**: `isLegalTarget` admits a hunted animal while he is
   hungry with nothing to eat, never a pet and never one in a pen (`safety/Hunting.java`).

## Where the four planned phases actually landed

| phase | what was planned | what shipped, by 0.87.0 | what did not |
|---|---|---|---|
| 1 — **Hands** | real block placement, container read/write, smelting, doors, navigator work, attack timing | all of it: `FakeActor.placeAt` (stairs, slabs, doors, beds, signs, torches, chest facing), `Containers`, `startSmelt`, `OpenDoorGoal`/`OpenFenceGateGoal`, `STEP_HEIGHT`, `ATTACK_SPEED` | a fight that continues after the first hit — shipped later, in 0.84.0 |
| 2 — **Exactly what a player does** | the fake actor and one `use` verb, stations, XP | all of it: `use` (`useOnBlock`, `useOnEntity`, `useOnHanging`), enchanting, anvil, brewing, smithing, loom, cartography, grindstone, and real XP with the player curve | bows, crossbows, tridents (see blocker 1) |
| 3 — **Travelling** | boats, minecarts, ridden animals, elytra, ladders, sleeping, portals | boats and minecarts as a passenger, ladders and vines, portal following with bag and levels | steering anything, elytra, sleeping |
| 4 — **Living in the world** | farming, animals, beehives, fishing, redstone, signs, trading, decoration | tilling, sowing, bone meal, the harvest-and-replant cycle, breeding, leads, shearing, milking, taming, name tags, signs, item frames, jukeboxes, beehives, TNT, levers, buttons, repeaters, note blocks, villager trading | fishing, driving pistons and redstone graphs, armour stands, beacons |

## What this means for "everything a player can do"

It is closer than the old document claimed, and the shape of what is left has changed. Of the 150 rows
below: **94 are yes** — 85 with a named in-game class behind them and 9 more that are one API call with no
class isolating them — **12 are partial**, **10 are untested**, and **31 are no**, of which roughly a third
are structural (sleeping, elytra, crits, sailing a boat by hand) rather than unimplemented. One row is
answered from the evidence, one is incidental and one is `n/a`. The one row that moved since 0.87 is
"kill a mob and take the loot", from partial to yes, and that is the whole of the player-visible change.

The remainder that a player would actually notice is short and is listed in order at the end of this
document. The hunting rule, which was the one genuine gap rather than a nicety, **shipped at 0.89.0**, and
with it the guard that keeps TNT, fire and lava away from the owner's things.

## Area 1 — combat, defence, effects

Three shape facts in 26.3 govern this area, and they are why the `no`s here are mostly structural:

- **There is no `SwordItem`.** Gear behaviour is data components: `DataComponents.WEAPON`,
  `BLOCKS_ATTACKS`, `ATTACK_RANGE`, `KINETIC_WEAPON`, `PIERCING_WEAPON`, `ATTRIBUTE_MODIFIERS`. Swords are
  plain `Items.IRON_SWORD` etc. carrying those components.
- **`BlocksAttacks` is the shield.** The block behaviour lives in the component and is consumed by
  `LivingEntity.applyItemBlocking`, which `hurtServer` calls — so any `LivingEntity` using a shield blocks,
  Cobbie included, at zero new code.
- **`Mob.doHurtTarget(ServerLevel, Entity)` is a real player-ish damage pipeline**: attribute damage, the
  weapon's `getDamageSource`, `EnchantmentHelper.modifyDamage`, `getAttackDamageBonus`, `hurtServer`,
  knockback, `hurtEnemy`, `doPostAttackEffects`. What it does not do is crit, sweep, attack-strength
  scaling or `Player`-only statistics.

## Area 2 — movement and traversal

He walks the way a `PathfinderMob` walks, with `MOVEMENT_SPEED 0.32`, `FOLLOW_RANGE 48` and
`STEP_HEIGHT 1.0` (`:459-472`), on a `GateAwareNavigation` subclass of the ground navigator (`:424`), plus
a goal list of `FloatGoal / GatedMeleeAttack / OpenDoorGoal / OpenFenceGateGoal / LookAtPlayerGoal /
RandomLookAroundGoal` (`:481-503`) and a tick-driven owner chase.

What is not a pathfinder's job is handled by hand and is the interesting half of this area: `swimTick`,
`climbTick`, `hazardRescueTick`, `followThroughPortal` and `getMaxFallDistance`. Each of those exists
because the pathfinder has no node for it.

## Area 3 — inventory, crafting stations and progression

The bag is a flat `SimpleContainer` (`:414`) of `inventory_size` slots, default 45, and the held tool is a
bag slot that has been raised into the hand rather than a hotbar selection. Everything that needs a
`Player` inventory — a menu, a `Slot`, shift-click — is therefore absent by construction, and every station
instead reads and writes the block entity it stands at.

Two decisions came out of this area and both are worth recording:

- **Hunger is the game's, not a copy.** `Hunger.Actor` is a `FakePlayer` whose food bar, health and effects
  *are* Cobbie's, so `FoodData.tick` runs unchanged and no food value is written down in this mod. That is
  what turned a design question into a difference that no longer exists.
- **The crafting table is a requirement, not a decoration.** `craft` from the bag still works for a 2×2
  recipe; anything needing a 3×3 must have the table within reach, and a special recipe is refused rather
  than invented.

## Area 4 — world, blocks, mobs and farming

The one fact that governed this whole area used to be "every right-click takes a `Player`". It still does —
`ServerPlayerGameMode.useItemOn`, `BlockBehaviour.useItemOn`/`useWithoutItem`, `Player.interactOn`,
`Player.openMenu`, `Player.startSleepInBed` — but there is now an actor for it, so the interesting question
per row is no longer "can he" but "does anything prove he did".

Placement deserves its own sentence, because it is where the old document was most wrong. A placed block
is now whatever `ServerPlayerGameMode.useItemOn` decides from a real `BlockHitResult`: two halves of a
door, a bed's head, a wall torch instead of a floor one, a stair's half, a sign's rotation and a chest
facing away from the placer. `CobbieBlockStateTest` places each one twice — once by Cobbie and once by the
owner standing in the identical spot — and requires the two blockstates to agree property by property. That
is the strongest evidence in this document, and it is the reason rows 294-299 are `yes` rather than
`partial`.

## The real remainder, ordered by what a player would notice first

One line each, in the order a person playing with him would hit them. Nothing here is a re-run of work
that shipped; every item is either absent, partial, or real but unproven.

1. **He pops blocks.** `destroyBlock` takes the whole block in one call (`:2685`): no swing, no crack, no
   tool-dependent duration. The largest remaining fidelity gap.
2. **Bows, crossbows, tridents.** One missing thing — a hold-and-release pair in the actor. Everything
   one-click already works.
3. **He cannot drive what he rides.** A boat or minecart carries him and nothing steers; a saddled animal
   refuses him entirely.
4. **Mending never fires.** His levels are real, but the repair lives on `Player`'s experience path. A loop
   in `absorbExperience` (`:3412`) is the whole fix.
5. **Tool-on-material anvil repair.** Tool-on-tool and books work; an iron ingot on an iron pickaxe does
   not.
6. **Cooked food.** He can now kill for meat (0.89.0) and he can smelt, but nothing joins the two: a
   hunted cow gives raw beef, and nobody has written "cook what I just took".
7. **Cats, saplings, silk touch and a picked-up water bucket** — real code paths, no test. Three cheap
   cases in `CobbieTailTest` and one in `CobbieMineTest` would turn them into facts.
8. **A dead body stays dead.** Identity, bag and levels persist, and the memory book is keyed by owner, so
   a respawn hook is all that is missing.
9. **Splash and lingering potions, snowballs, eggs, ender pearls** are reachable through `use` in the air
   and unproven, and none of them chooses an aim.
10. **Double slabs, sugar cane on a bank, tall flowers** — placement paths exist, no case asserts them.
11. **Reply with an effect he cannot see:** a thorns hit and an active potion effect are never narrated,
    which reads as a missing capability even though both work.
12. **Structural, and staying that way:** sleeping in a bed, elytra, crits, sweep, steering a saddled
    animal, fishing (the bobber dies), pistons and redstone graphs, armour stands, beacons. Each is
    `Player` state or a second visible player, and none of them is worth what it would cost.
